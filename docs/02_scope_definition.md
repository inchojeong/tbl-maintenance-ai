# 02. 개발 범위 정의

## 1. 범위 구분 원칙

시제품 기간(약 5주)을 전제로 **시연 시나리오(엔진 오일 압력 저하)를 끝까지 통과시키는 기능을 필수**, UX·안정성 보강을 권장, 군 실무 수준 기능을 제외로 둔다.

## 2. 필수 구현 (P0)

| 기능 ID | 기능명 | 설명 |
|---|---|---|
| F-01 | 텍스트 질의 입력 | 좌측 패널에서 증상 텍스트 전송 |
| F-02 | 질의 구조화 | system/symptom/risk/components/view_target 추출 |
| F-03 | 더미 교범 RAG | ChromaDB + 메타필터 + 근거 표시 |
| F-04 | 대표 시나리오 2~3개 | 오일압력, (선택)랜딩기어/로터 |
| F-05 | 3D 외형 표시 | GLB 로드·OrbitControls |
| F-06 | 구역 하이라이트 | `ENGINE_ZONE`/`ENGINE_PANEL_*` |
| F-07 | 클릭 카메라 이동 | viewTarget 프리셋 + GSAP |
| F-08 | 패널/투명화 | hide 또는 opacity |
| F-09 | 부품 하이라이트 | `OIL_FILTER` 등 |
| F-10 | AI↔3D 연동 | `view_target_id` 매핑 |
| F-11 | 가이드↔3D | 단계별 viewTarget 전환 |
| F-12 | 더미 고지 | 교범 장·절·페이지 + is_dummy |
| F-13 | 유사고장·PHM 표시 | Mock/API 조회 |
| F-14 | 정비결과 등록 | SQLite 저장 |
| F-15 | 데모모드 | 고정 JSON fallback |

## 3. 권장 구현 (P1)

|---|---|

| F-24 | 부품 Outline/점멸 |

## 5. 기존 프로토타입 대비 범위

| 기존(Mock UI) | 본 시제품 |
|---|---|
| 다페이지 라우트 | One-Screen 중심(+하단 탭) |
| PNG 디지털트윈 | GLB 3D |
| 하드코딩 답변 | LLM+RAG+데모 fallback |
| 백엔드 없음 | FastAPI |
| 상태관리 없음 | Zustand |

## 6. 가정 / 결정 필요 / 리스크

| 구분 | 내용 |
|---|---|
| 가정 | 엔진 오일 시나리오 1개만으로도 심사는 가능 |
| 가정 | GLB는 공개 헬리콥터 모델을 단순화하거나 프록시 메시로 대체 가능 |
| 결정 필요 | LLM: OpenAI vs Gemini (기본 OpenAI) |
| 결정 필요 | Embedding: API vs 로컬 ST (오프라인 우선 시 로컬) |
| 리스크 | Blender 오브젝트 분리 지연 → 박스 프록시로 대체 |
| 리스크 | API 키/네트워크 → 데모모드 필수 |

## 7. 완료 게이트

P0 기능이 대표 시나리오 E2E(문서 `11`, `13`)를 통과하면 시제품 핵심 완료로 본다.
