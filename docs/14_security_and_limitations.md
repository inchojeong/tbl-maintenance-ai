# 14. 보안 및 제한사항

## 1. 보안·규정 원칙

본 시스템은 **공모전 시연용 기술 검증 시제품**이다. 실제 군 정비판단, 작업지시, 비행가능 판정에 사용할 수 없다.

## 2. 금지사항

- 실제 수리온 기술교범 원문 수록/학습
- 실제 내부 구조의 정밀 재현(공개자료 수준 가상 모델만)
- 실제 군용 부품번호·정비허용치 사용
- 실제 고장사례와 혼동되는 표현(반드시 모의/더미 명시)
- 생성형 AI 출력을 확정 정비지식으로 단정
- 운영 환경에 실식별 부대·인적 민감정보 저장

## 3. 필수 UI 고지

모든 주요 화면(헤더 또는 하단)에 표시:

> 본 시제품의 항공기 형상, 교범, 부품명, 센서값, 고장사례 및 점검절차는 기술 검증을 위해 임의 가공한 모의 데이터이며 실제 수리온 정비자료와 무관합니다.

교범·PHM·사례 카드에 `is_dummy` / `모의` 배지 필수.

## 4. 데이터·API 보안 (시제품 수준)

| 항목 | 조치 |
|---|---|
| 비밀키 | `.env`만 사용, 저장소 커밋 금지 |
| CORS | 개발 오리진만 허용 |
| 업로드 | 음성/이미지 크기·MIME 제한 |
| 로그 | 질의 텍스트만, 개인정보 금지 |
| DB | 로컬 SQLite, 배포 시 볼륨 분리 |

## 5. AI 제한

- view_target_id whitelist
- 교범 근거 없는 절차 생성 금지
- 비행 가능/불가 자동판정 문구 금지
- confidence 낮거나 근거 없으면 보수적 안내

## 6. 기술적 제한사항

| 제한 | 설명 |
|---|---|
| 3D 정밀도 | 시연용 단순 모델 |
| 시나리오 수 | 대표 2~3개 |
| 오프라인 | 데모모드로 가능, 실 LLM은 불가 |
| 모바일 | 비목표 |
| 동시 사용자 | 시연 1~소수 |

## 7. 잔여 리스크

| 리스크 | 완화 |
|---|---|
| 심사자가 실체계로 오해 | 고지·더미 배지 |
| API 장애 | 데모모드 |
| GLB 성능 | 용량/폴리곤 제한 |
| 환각 | Pydantic+whitelist+RAG 근거 |
